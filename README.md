# TempMail Pro — monorepo

One repo, two services. This is the production layout for TempMail Pro
(https://tempmailpk.com/).

## Layout

- `frontend/` — React + Vite app. Static deploy on Vercel. Root directory in
  Vercel: `frontend/`. It already contains `vercel.json`.
- `backend/` — Express service. Long-lived deploy on Render (later). Root
  directory in Render: `backend/`. It owns Mail.tm accounts, inbox polling,
  SSE streaming, and token-based inbox tracking.
- `render.yaml` — prepared Render config for later. It does not deploy
  anything by itself.

## Why two services

The old single server served the Vite frontend and held inbox/token state in
in-memory Maps. That state is lost on Vercel serverless cold-starts, scaling,
or termination, so live inboxes and mail delivery were unreliable there. The
backend now runs as a long-lived process, and the frontend is static.

## Local development

```bash
# backend (port 10000)
npm run dev:backend

# frontend (port 5173, /api proxied to the backend)
npm run dev:frontend
```

## Production env vars

Frontend (Vercel):

- `VITE_API_BASE` — Render backend URL, no trailing slash, no `/api` suffix.
  Example: `https://tempmail-pro-backend.onrender.com`
  If unset, the frontend falls back to same-origin `/api`, which will not work
  on a static Vercel deploy.

Backend (Render):

- `PORT` — set by Render
- `CORS_ORIGIN` — comma-separated frontend origins, e.g.
  `https://tempmailpk.com,https://www.tempmailpk.com`
- `MAIL_TM_API_BASE` — default `https://api.mail.tm`

## What was NOT changed in this move

- No inbox/token storage change: state is still in-memory in `backend/server.ts`.
  Redis/database persistence is the next step, not part of this move.
- No binary public assets were moved by the API in this branch: PWA icons are
  regenerated by `frontend/scripts/generate-pwa-icons.js` during `npm run build`.
  `frontend/public/favicon.ico` needs to be copied from `main` when this branch
  is checked out locally, before a production frontend build that requires it.
  PWA icons and apple-touch-icon are regenerated by the build script.
- `.history/` and `.aistudio/` editor snapshots were intentionally left out.

## Deploy order (later)

1. Deploy backend to Render first, verify `GET /health` and a real Mail.tm
   account + SSE stream.
2. Set `VITE_API_BASE` in Vercel to the Render URL, deploy frontend.
3. Verify signup -> inbox -> live mail end to end on tempmailpk.com.
